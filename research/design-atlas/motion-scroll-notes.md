## Durations
- NN/g: most UI animation 100–500 ms; simple feedback (checkbox, toggle) ~100 ms; modal entering 200–300 ms; "100–400 ms is appropriate, with 400ms being a very slow animation, to be used only for big movements across large screens"; 500 ms feels "like a real drag"; entering slightly longer than exiting (popup 300 ms in, 200–250 ms out); the more frequent, the shorter; ease-out most common; ease-in can feel unresponsive. https://www.nngroup.com/articles/animation-duration/
- Material (M1, legacy but still the only device-scaling numbers): mobile typical 300 ms; large/complex full-screen 375 ms; entering 225 ms; leaving 195 ms; tablet ~30% longer (300→390 ms); wearables ~30% shorter (300→210 ms); desktop 150–200 ms. Easing: standard cubic-bezier(0.4,0,0.2,1), deceleration (0,0,0.2,1), acceleration (0.4,0,1,1), sharp (0.4,0,0.6,1). https://m1.material.io/motion/duration-easing.html
- M3 duration tokens (androidx docs + M3 tokens page): short1 50, short2 100, short3 150, short4 200; medium1 250, medium2 300, medium3 350, medium4 400; long1 450, long2 500, long3 550, long4 600; extra-long1 700, extra-long2 800, extra-long3 900, extra-long4 1000 ms. "duration should increase as the area or traversal of an animation increases". https://raw.githubusercontent.com/material-components/material-components-android/master/docs/theming/Motion.md ; https://m3.material.io/styles/motion/easing-and-duration/tokens-specs
- M3 usage examples (subagent read of M3 page): selection controls 200 ms Standard; FAB→sheet 400 ms Emphasized; card→full screen 500 ms Emphasized; ambient carousel 1000 ms. M3 page says easing/duration tokens are now "legacy", superseded by springs.
- Carbon: duration-fast-01 70 ms, fast-02 110, moderate-01 150, moderate-02 240, slow-01 400, slow-02 700 (background dimming). Productive vs expressive (expressive reserved for "occasional, important moments"). Productive standard (0.2,0,0.38,0.9), entrance (0,0,0.38,0.9), exit (0.2,0,1,0.9); expressive standard (0.4,0.14,0.3,1), entrance (0,0,0.3,1), exit (0.4,0.14,1,1). https://carbondesignsystem.com/elements/motion/overview/
- Apple HIG Motion: no duration/easing numbers; brief and precise, make motion optional, let people cancel it. https://developer.apple.com/design/human-interface-guidelines/motion

## Easing (M3)
- standard (0.2,0,0,1); standard-decelerate (0,0,0,1); standard-accelerate (0.3,0,1,1); emphasized-decelerate (0.05,0.7,0.1,1); emphasized-accelerate (0.3,0,0.8,0.15); emphasized = path `M 0,0 C 0.05,0, 0.133333,0.06, 0.166666,0.4 C 0.208333,0.82, 0.25,1, 1,1` (no single bezier; M3 says use Standard as CSS fallback; material-web approximates (0.2,0,0,1)); legacy (0.4,0,0.2,1); linear (0,0,1,1). Sources: Motion.md above; M3 tokens page (subagent).
- Container transform default easing listed as (0.4,0,0.2,1) FastOutSlowIn in MDC-Android doc.
- CSS `linear()` easing: Baseline, available across browsers since Dec 2023; allows values outside 0–1 (overshoot) → can approximate springs. https://developer.mozilla.org/en-US/docs/Web/CSS/easing-function/linear

## Springs
- M3 Expressive announced 2025-05-13 (Android Show: I/O Edition), Compose `MotionScheme` added 1.5.0-beta01. Two schemes (expressive, standard) × spatial/effects × fast/default/slow. Spatial may overshoot (position, size, rotation, corners); effects never overshoot (color, opacity). Values from androidx source ExpressiveMotionTokens.kt / StandardMotionTokens.kt:
  - expressive: fast spatial 0.6/800, default spatial 0.8/380, slow spatial 0.8/200; effects fast 1.0/3800, default 1.0/1600, slow 1.0/800
  - standard: spatial fast 0.9/1400, default 0.9/700, slow 0.9/300; effects same as expressive
  - M3 web equivalents (cubic-bezier + duration): expressive fast spatial (0.42,1.67,0.21,0.90) 350 ms; expressive default spatial (0.38,1.21,0.22,1.00) 500 ms; expressive slow spatial (0.39,1.29,0.35,0.98) 650 ms; standard spatial (0.27,1.06,0.18,1.00) 350/500/750 ms; effects fast (0.31,0.94,0.34,1) 150 ms, default (0.34,0.80,0.34,1) 200 ms, slow (0.34,0.88,0.34,1) 300 ms.
  - https://m3.material.io/styles/motion/overview/how-it-works ; https://m3.material.io/styles/motion/overview/specs ; https://developer.android.com/reference/kotlin/androidx/compose/material3/MotionScheme ; https://raw.githubusercontent.com/androidx/androidx/androidx-main/compose/material3/material3/src/commonMain/kotlin/androidx/compose/material3/tokens/ExpressiveMotionTokens.kt ; https://blog.google/products/android/material-3-expressive-android-wearos-launch/
  - MDC-Android `motionSpring*` attrs (lib 1.13.0+) match the standard scheme: FastSpatial 0.9/1400 (switches, buttons), DefaultSpatial 0.9/700 (bottom sheet, nav drawer), SlowSpatial 0.9/300 (full screen), effects 1/3800, 1/1600, 1/800.
- Compose `Spring`: DampingRatioNoBouncy 1.0, LowBouncy 0.75, MediumBouncy 0.5, HighBouncy 0.2; StiffnessHigh 10000, Medium 1500, MediumLow 400, Low 200, VeryLow 50. Default `spring()` = NoBouncy + StiffnessMedium. https://developer.android.com/reference/kotlin/androidx/compose/animation/core/Spring
- SwiftUI: `spring(response: 0.5, dampingFraction: 0.825, blendDuration: 0)` defaults; `spring(duration: 0.5, bounce: 0)`; `interactiveSpring` response 0.15, damping 0.86, blend 0.25; `.default` on iOS 17+ = spring(response 0.55, dampingFraction 1.0) (before iOS 17: easeInOut); `.smooth` bounce 0, `.snappy` bounce 0.15, `.bouncy` bounce 0.3, all duration 0.5; bounce 0 = critically damped, negative = overdamped; duration = perceptual settling time. bounce → damping ratio `1 − bounce` (from Motion source comment, unverified against Apple). https://developer.apple.com/documentation/swiftui/animation/spring(response:dampingfraction:blendduration:) ; https://developer.apple.com/documentation/swiftui/spring
- Motion (motion.dev): renamed from Framer Motion 2024-11-12 (`motion` 11.11.12; import `motion/react`). https://motion.dev/blog/framer-motion-is-now-independent-introducing-motion . Majors: 12.0.0 2025-01-20, 13.0.0 2026-08-05, 14.0.0 2026-10-02. Spring source defaults stiffness 100, damping 10, mass 1, bounce 0.3, visualDuration 0.3 s (docs page says stiffness 1 – looks like a docs error). `visualDuration` since 11.12.0. Default transitions when type unset: transforms spring stiffness 500 damping 25; scale stiffness 550 damping 30; >2 keyframes tween 0.8 s; opacity/color tween 0.3 s ease [0.25,0.1,0.35,1]. https://motion.dev/docs/react-transitions ; https://github.com/motiondivision/motion
- Reanimated: v4 `withSpring` defaults changed: damping 120, stiffness 900, mass 4 (duration-based: 550, dampingRatio 1; perceptual, real time ≈1.5×); v3 was damping 10, stiffness 100, mass 1. Old defaults exported as `Reanimated3DefaultSpringConfig`. `withTiming` default 300 ms, `Easing.inOut(Easing.quad)`. v4.0.0 released 2025-07-23; New Architecture only; needs `react-native-worklets`; CSS animations/transitions API in `style`. https://docs.swmansion.com/react-native-reanimated/docs/animations/withSpring/ ; https://docs.swmansion.com/react-native-reanimated/docs/guides/migration-from-3.x/ ; https://swmansion.com/blog/reanimated-4-stable-release-the-future-of-react-native-animations-ba68210c3713

## Principles
- Disney 12 → UI (IxDF): squash & stretch = tactile press; anticipation = hover hint before action; staging = one focal point; pose-to-pose = keyframed component states; follow-through/overlap = lead element first, text follows; slow in/out = easing; arcs = curved paths (Dock); secondary action = confetti after submit; timing = duration conveys info (upload length tied to size); exaggeration = emphasis, tone down if annoying; solid drawing = consistent shadows/perspective; appeal = personality. https://ixdf.org/literature/article/ui-animation-how-to-apply-disney-s-12-principles-of-animation-to-ui-design
- UX in Motion (Issara Willenskomer): easing, offset & delay, parenting, transformation, value change, masking, overlay, cloning, obscuration, parallax, dimensionality, dolly & zoom. "You want all motion to always ease." https://uxmag.com/articles/creating-usability-with-motion-the-ux-in-motion-manifesto
- Material transition patterns: container transform (element with container becomes another: card→details, FAB→page); shared axis x/y/z (spatial/navigational relationship: onboarding x, stepper y, parent-child z); fade through (unrelated destinations: bottom nav tabs); fade (enter/exit within screen: dialog, menu, snackbar). Source: Motion.md (MDC-Android).
- Saffer microinteractions: trigger (manual or system), rules (invisible, learned through feedback), feedback (visual/sound/haptic), loops & modes ("get data every 30 seconds"; modes for preferences). Secondary summaries: https://cieden.com/book/sub-atomic/microinteractions/structure-of-microinteractions ; https://uxdesign.cc/think-smaller-engaging-users-through-microinteractions-9f10372f2e1b ; book: https://www.oreilly.com/library/view/microinteractions/9781449342760/

## Loading / response
- NN/g response limits: 0.1 s feels instantaneous (no feedback beyond result); 1 s keeps flow (beyond ~1 s show busy); 10 s attention limit (percent-done + cancel + expected finish). https://www.nngroup.com/articles/response-times-3-important-limits/
- NN/g skeletons: <1 s no indicator needed; spinner for 2–10 s waits in a single module; skeleton for full-page loads under 10 s; >10 s progress bar with estimate; animated shimmer can distract/accessibility issue; frame-display skeleton ≈ spinner (avoid). https://www.nngroup.com/articles/skeleton-screens/

## View Transitions
- MDN API overview: `document.startViewTransition()`, `Element.startViewTransition()`, `@view-transition`, `view-transition-name`, `view-transition-class`, `view-transition-scope`, `:active-view-transition`, `:active-view-transition-type()`, pseudo-elements `::view-transition`, `-group()`, `-image-pair()`, `-old()`, `-new()`; events `pageswap`, `pagereveal`. https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API
- Same-document Baseline Newly available 2025-10-14 with Firefox 144 (also view-transition-class, match-element, :active-view-transition); Firefox initial release lacks view transition types. Chrome/Edge 111, Safari 18. https://web.dev/blog/same-document-view-transitions-are-now-baseline-newly-available ; https://developer.chrome.com/docs/web-platform/view-transitions/same-document
- Cross-document: both pages need `@view-transition { navigation: auto; }`, same origin; not for URL-bar navigations, bookmarks, reloads; Chrome skips if navigation >4 s (TimeoutError); `pagereveal` listener in classic parser-blocking head script; `<link rel="expect" blocking="render" href="#id">` (Chromium only). Support: Chrome/Edge 126, Safari 18.2. https://developer.chrome.com/docs/web-platform/view-transitions/cross-document
- caniuse cross-document: Chrome 126+, Safari 18.2+ (incl. iOS), Firefox 143 disabled by default, 144+ "partial support" (bug 1860854). https://caniuse.com/cross-document-view-transitions
- Interop 2026 includes View Transitions (cross-document) and Scroll-driven Animations among 20 focus areas. https://web.dev/blog/interop-2026 ; https://webkit.org/blog/17818/announcing-interop-2026
- React 19.3 `<ViewTransition>` (import from 'react'): activated only by Transitions, Suspense, useDeferredValue; React calls startViewTransition itself; props name/enter/exit/update/share/default (+ type-keyed objects); `default="none"` turns off others. https://react.dev/reference/react/ViewTransition
- Next.js 16.4 guide (lastUpdated 2026-09-10): App Router works with no config; React 19.3 includes `<ViewTransition>` and `addTransitionType`; uses types + view-transition-class (Chromium 125+, recent Safari/Firefox); shared element via same `name`; `share="morph"` + `default="none"`; `<Link transitionTypes={['nav-forward']}>`; put wrapper in each page.tsx not layout; morph only when destination renders in same commit (prefetched); hit-testing skips named participants during transition; example timings: old fade 150 ms ease-in + slide 400 ms ease-in-out, new fade 210 ms ease-out delayed 150 ms; morph 400 ms with blur(3px) mid-flight; reduced motion: set ::view-transition-* animation-duration 0s. https://nextjs.org/docs/app/guides/view-transitions
- Astro: `<ClientRouter />` from `astro:transitions`; `transition:name`, `transition:animate` (fade default, initial, slide, none), `transition:persist`; fallback animate/swap/none; router disables animations under prefers-reduced-motion; events astro:before-preparation, after-preparation, before-swap, after-swap, page-load; bundled module scripts run once → re-init on astro:page-load; native cross-document option without the router. https://docs.astro.build/en/guides/view-transitions/

## Scroll-driven animations (CSS)
- Concepts: scroll progress timeline `scroll(<scroller> <axis>)` scroller nearest|root|self, axis block|inline|x|y; view progress timeline `view(<axis> <inset>)`; named `scroll-timeline`, `view-timeline` (names start with --); `timeline-scope` for non-ancestors; `animation-range` ranges cover, contain, entry, exit, entry-crossing, exit-crossing; ranges use the untransformed box; runs off main thread for compositor props. Progress bar: `animation: grow-progress auto linear; animation-timeline: scroll();` with transform-origin 0 50%. https://developer.chrome.com/docs/css-ui/scroll-driven-animations
- Support: Chrome/Edge 115+ (July 2023); Safari 26.0 (2025-09-15) "Added support for Scroll-driven Animations"; Safari 26.5 (2026-05-11) fixed `scroll` range name and dynamic animation-play-state pause; Safari 26.4 threaded scroll-driven animations (third-party, unverified). https://webkit.org/blog/17333/webkit-features-in-safari-26-0/ ; https://developer.apple.com/documentation/safari-release-notes/safari-26_5-release-notes
- Firefox: `layout.css.scroll-driven-animations.enabled` on by default in Nightly since 136, off in release; still flagged in stable as of Firefox 152 (June 2026) per buildmvpfast blog; caniuse lists Firefox ≤159 not supported and 160 supported (future release, planned). https://developer.mozilla.org/Firefox/Experimental_features ; https://www.buildmvpfast.com/blog/css-scroll-driven-animations-replace-js-2026 ; https://caniuse.com/mdn-css_properties_animation-timeline (global usage 87.84% at fetch)
- Polyfill: flackr/scroll-timeline (`https://flackr.github.io/scroll-timeline/dist/scroll-timeline.js`), supports CSS animation-timeline + JS ScrollTimeline/ViewTimeline; CSS must be same-origin or inline. https://github.com/flackr/scroll-timeline
- Stacking-cards CSS demo (Bramus): timeline on container `view-timeline-name: --cards-element-scrolls-in-body`; per card `animation-range: exit-crossing calc(index0/n*100%) exit-crossing calc(index/n*100%)`; keyframe `scale(calc(1.1 - 0.1 * reverse-index))`. https://scroll-driven-animations.style/demos/stacking-cards/css/

## Motion (React) scroll
- useScroll returns scrollX/Y, scrollX/YProgress; options container, target, axis, offset (default ["start start","end end"]), trackContentSize; offsets like ["start end","end start"]; can run hardware-accelerated via ScrollTimeline when progress drives opacity or useTransform-supported styles (e.g. filter). Progress bar: `const scaleX = useSpring(scrollYProgress)`. https://motion.dev/docs/react-use-scroll
- useTransform(value, input, output, {clamp}) clamp default true; function form `useTransform(() => x.get()*2)`; map form for multiple outputs. https://motion.dev/docs/react-use-transform

## Lenis
- Setup: `new Lenis({ autoRaf: true })` or with GSAP: `lenis.on('scroll', ScrollTrigger.update); gsap.ticker.add((time) => lenis.raf(time * 1000)); gsap.ticker.lagSmoothing(0);`. Options lerp 0.1, duration 1.2 (ignored when lerp set), smoothWheel true, syncTouch false (unstable iOS<16), prevent(node), anchors, allowNestedScroll (costly), autoResize true. CSS `lenis/dist/lenis.css`. `data-lenis-prevent(-wheel|-touch|-vertical|-horizontal)`. Limitations: no native CSS scroll-snap (use lenis/snap); Safari capped at 60 fps (30 fps low power); no smoothing over iframes; position:fixed lag on pre-M1 macOS Safari. https://github.com/darkroomengineering/lenis

## Viewport units
- lv* = toolbars retracted; sv* = toolbars expanded; dv* = current, clamped between; dv updates are throttled/debounced (not 60 fps); support dv* Chrome 108, Firefox 101, Safari 15.4; keyboard does not affect units by default. https://web.dev/blog/viewport-units

## Scroll video / image sequence
- Scrubbing seeks to nearest keyframe → encode dense keyframes. muffinman: keyframe every 5 vs every 100 frames ≈5× size (MP4 146 KB→845 KB; WebM 195→1038 KB); `ffmpeg -i in.mp4 -vcodec libx264 -x264-params keyint=10:scenecut=0 out.mp4`, VP9 `-g 10`; Firefox needs WebM (MP4 choppy), iOS Safari poor with WebM → serve both; Safari smoothest. https://muffinman.io/blog/scrubbing-videos-using-javascript/
- hontran: `-g 1` every frame a keyframe; scale to rendered box; `-movflags faststart`; `-an`; `preload="auto"`; `muted playsinline`; never call play(); guard NaN duration (wait loadedmetadata); WebM source first, MP4 fallback. Commands: `ffmpeg -i in.mov -vf scale=1280:-2 -r 30 -movflags faststart -vcodec libx264 -crf 23 -g 1 -pix_fmt yuv420p -an out.mp4`; `ffmpeg -i in.mov -vf scale=1280:-2 -r 30 -c:v libvpx-vp9 -crf 32 -b:v 0 -g 1 -pix_fmt yuv420p -an -row-mt 1 out.webm`. https://www.hontran.dev/blog/scroll-scrubbed-video-stutters-fix
- GSAP scroll-video guide suggests keyframe every 6 frames as middle ground (search snippet, unverified).
- Canvas image sequence (CSS-Tricks, AirPods Pro): fixed canvas, numbered frames, frame index from scroll; GSAP forum: swapping img src is slow → preload; WebP shrinks; image grids crash iPhones; 60–180 frames typical (secondary blog). https://css-tricks.com/?p=308477 ; https://gsap.com/community/forums/topic/25188-airpods-image-sequence-animation-using-scrolltrigger/
- Apple pages (subagent, HTML inspection 2026-10-10): airpods-pro uses `VideoScrub` + `ParallaxImage` + 16 `data-anim-scroll-group`; macbook-pro 21 scroll groups, `data-anim-keyframe`, sticky stages.

## CSS 3D parallax
- Chrome "Performant parallaxing" (2016, dated): scroller `perspective: 1px; perspective-origin: 0 0; overflow-y: scroll`; child `transform-origin: 0 0; transform: translateZ(-2px) scale(3)`; scale = (perspective − z)/perspective; intermediate elements flatten unless preserve-3d; Mobile Safari needed sticky workaround; scroll events are best-effort, background-position repaints. https://developer.chrome.com/blog/performant-parallaxing

## Performance
- web.dev: restrict animations to transform and opacity; avoid layout/paint props; will-change sparingly, add shortly before, remove after; DevTools Performance panel, paint flashing, FPS meter. https://web.dev/articles/animations-guide
- MDN will-change: "last resort"; overuse slows page; set from script before/after; creates stacking context up front; applies to subtree. https://developer.mozilla.org/en-US/docs/Web/CSS/will-change
- INP: good ≤200 ms, needs improvement ≤500 ms, poor >500 ms (p75); input delay + processing + presentation delay. https://web.dev/articles/inp

## Accessibility
- WCAG 2.3.3 Animation from Interactions (AAA): motion triggered by interaction can be disabled unless essential; parallax named as common non-essential; technique C39 prefers-reduced-motion. https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html
- WCAG 2.2.2 Pause, Stop, Hide (A): auto-starting moving/blinking/scrolling content lasting >5 s alongside other content needs pause/stop/hide. https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html
- MDN prefers-reduced-motion: `reduce` / `no-preference`; OS mapping macOS ≤15 Display > Reduce motion, macOS 26 Accessibility > Motion > Reduce motion, iOS Accessibility > Motion, Windows 11 Visual Effects > Animation Effects, Android 9+ Remove animations; Firefox `ui.prefersReducedMotion`; scaling/panning large objects are vestibular triggers; example replaces pulse with dissolve. https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion
- CSS carousels `::scroll-button()` / `::scroll-marker`: MDN marks experimental, limited availability (not Baseline). https://developer.mozilla.org/en-US/docs/Web/CSS/::scroll-button
